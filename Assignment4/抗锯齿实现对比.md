# 抗锯齿实现对比：双线性 Splat 与 3×3 覆盖率采样

> 作业 4 Bonus 的两种抗锯齿实现笔记。代码位置：`code/main.cpp`。
> 本文所有数字都是在本机实测得到（700×700 画布，1001 个曲线采样点，4 个控制点 `(180,420) (210,300) (420,220) (490,545)`）。

![三种画法对比（5 倍放大）](images/aa_compare_3way.png)

**一句话结论**：Splat 是「能量分摊」，实现便宜、灰阶连续，但覆盖率不代表面积、会饱和；3×3 覆盖率采样是「面积估计」，结果接近物理真值、可解释性强，但多了 9 倍距离计算、只有 9 级灰度。

> 命名说明：本文方法 B 常被叫「3×3 超采样」，严格说它是 **N 样本覆盖率采样（coverage sampling）**，与 MSAA 同语义，而不是 SSAA。两者的区别见 4.3 节。

---

## 1. 锯齿从哪来

屏幕上一条曲线是连续的一维集合，而画布是离散的像素网格。如果对每个采样点直接做

```cpp
window.at<cv::Vec3b>(y, x)[1] = 255;   // 非 0 即 255
```

就是在做**点采样（point sampling）**：一个像素要么被判定为「全在线上」，要么「完全不在」，中间状态被丢掉了。

用我们的实验数据看最清楚：

| 画法 | 有效像素 | 满值(255) | 中间值 | 灰阶种类 |
|---|---|---|---|---|
| 无 AA | 541 | 541 | **0** | **1** |

整个图像只有 1 种非零灰度。曲线的真实面积约 500 px²，但点采样把它画成了 541 个「全亮」像素——**多出来的、缺失的覆盖率，全部表现为阶梯状的硬边。**

> 补充一个容易误判的现象：某些缩放比例下曲线看起来像「虚线」，其实是 1px 硬边在显示缩小时产生的摩尔纹（moiré），不是曲线断裂。像素级检查可以确认这一点：曲线像素 8 邻域全连通，孤立点为 0。

## 2. 抗锯齿的统一框架

抗锯齿的本质只有一句话：**不再回答「这个像素在不在线上」，而是回答「这个像素有多少面积在线上」。**

记覆盖率 `α ∈ [0,1]`，最终颜色是

```
C_pixel = C_bg · (1 − α) + C_curve · α
```

在代码里两者共用同一个合成函数（`main.cpp:89`）：

```cpp
static void composite_coverage(const std::vector<float> &coverage, cv::Mat &window)
{
    const float alpha = std::min<float>(1.0f, coverage[..]);
    auto& pixel = window.at<cv::Vec3b>(y, x);
    pixel[1] = std::max<uchar>(pixel[1], static_cast<uchar>(255.0f * alpha + 0.5f));
}
```

`+ 0.5f` 是四舍五入（`uchar` 转换是截断），`min(1, ·)` 是给 Splat 准备的截断。

**两种方法的全部差异，在于 `coverage` 怎么算出来**：一个靠分摊，一个靠采样。

## 3. 方法 A：双线性 Splat（能量分摊）

### 3.1 做法

曲线上每个采样点不再只点亮一个像素，而是按其在像素内的相对位置 `(fx, fy)`，把 1 份「能量」分摊给周围 4 个像素（`main.cpp:115-148`）：

```
w00 = (1−fx)(1−fy)    w10 = fx(1−fy)
w01 = (1−fx)·fy       w11 = fx·fy
```

四个权重之和恒等于 1，所以**能量守恒！！！**：

```
coverage[x0  ][y0  ] += w00;
coverage[x0+1][y0  ] += w10;
coverage[x0  ][y0+1] += w01;
coverage[x0+1][y0+1] += w11;
```

注意这里是 `+=` 而不是 `=`：多个采样点落在同一像素时会累加，这正是「积分」的离散形式。

### 3.2 它到底在算什么

把每个采样点看成一个冲激 `δ`，用双线性核 `k`（一个半径 1、峰值 1 的帐篷函数）做卷积重建，再在像素上积分。这属于**后滤波（post-filtering）**：先在物体上生成连续信号，再在屏幕空间重建。

好处：输出是连续量，灰阶平滑（实测 231 种灰度），转折处不会出现硬接缝。

### 3.3 它的问题：覆盖率不等于面积

这是最值得记住的一点。采样点总数是固定的（1001 个），所以**总能量恒为 1001**，与曲线长度无关：

| 量 | 数值 |
|---|---|
| Splat 沉积的总能量 | 1001.0 |
| 曲线真实面积（用方法 B 估计） | ≈ 493 |
| 实测图像里覆盖率总和（截断后） | 707.2 |

也就是说，平均每个有效像素被沉积了约 2 次能量，**中间必然饱和**，被 `min(1, ·)` 砍掉的部分占 **29.3%**。

由此带来两个推论：

1. **亮度依赖于采样密度**：把 `t += 0.001` 改成 `t += 0.01`（采样点从 1001 降到 101），线条立刻变暗变细，因为没有足够能量把覆盖率顶到 1。**这不是 bug，是方法本身的性质**。
2. 要让它成为真正的面积估计，必须按采样间距归一化——比如用弧长参数化，或把权重乘以 `Δs`（相邻采样点的距离 / 像素面积）。

### 3.4 优缺点

| 优点 | 缺点 |
|---|---|
| 极便宜：每点 4 次加法 | 覆盖率不是面积，需要归一化 |
| 灰阶连续，边缘柔和 | 结果随采样密度变化（不够「稳健」） |
| 不依赖线段结构，单点即可 | 曲线密集处过饱和（自交、折返处会出现亮斑） |
| 天然支持「点云/粒子」类绘制 | 无法回答「这像素被覆盖了多少面积」 |

### 3.5 为什么是「泼溅」而不是「插值」

Splat 这个词来自「一个零尺寸的采样点被渲染成有面积的足迹，把贡献泼洒到周围像素上」——辐射度渲染、体渲染、点云表面泼溅（surface splatting）、3D Gaussian Splatting 都是同一个思路。

它和你熟悉的双线性插值用的是**同一个帐篷核**，只是数据流方向相反：

```
gather （插值）：out[i] = Σ_j f[j] · k(i − j)     权重摊在已知值上，结果是加权平均（≤ 输入最大值）
scatter（泼溅）：out[i] += Σ_j v[j] · k(i − j)    每个点往邻居泼，结果是累加（可超过 1）
```

写成矩阵就是 `out = K·f` 与 `out = Kᵀ·v`——**splat 是插值的转置（伴随算子）**。这不是巧合：CT 反投影、3DGS 的反向梯度都是同一个 `Kᵀ`。

为什么曲线必须用 scatter：曲线采样点是**稀疏且不规则**的。若对某个像素做 gather，它周围四个邻居可能一个点都没有，结果只能是 0，曲线会出现空洞；反过来从每个点往外泼，才能保证每个点都被画到。

| | gather | scatter |
|---|---|---|
| 适用 | 源是**规则网格**（贴图、深度图） | 源是**稀疏点集**（点云、粒子、曲线采样点） |
| 缺点 | 源稀疏时会漏采样 | 点密集时会重叠过饱和 |
| 例子 | 作业 3 的 `getColorBilinear(uv)` | 本文的 `rasterize_splat` |

也正因为 scatter 是累加，输出天然带有「密度」含义：**某像素的覆盖率 ∝ 落在它附近的采样点数量**。3DGS 里「高斯越密集颜色越实」就是这个道理，我们的线条亮度随 `t` 步长变化也是这个道理。

## 4. 方法 B：3×3 覆盖率采样（MSAA 语义）

### 4.1 做法

把曲线离散成折线后，对每条线段做三件事（`main.cpp:151-195`）：

1. **裁剪候选像素**：算线段的 AABB，外扩后只遍历附近的像素；
2. **每个像素取 9 个子采样点**，位置固定在 `x+1/6, x+1/2, x+5/6`（3×3 均匀网格）；
3. **判断子采样点是否被覆盖**：点到线段距离 `≤ 0.5`（线宽 1 像素 ⇒ 半宽 0.5）。

覆盖结果用 9 个 bit 记录，多条线段**按位或**取并集：

```cpp
if (distance_to_segment(sample, a, b) <= half_width)
    mask |= static_cast<unsigned short>(1u << (iy * n + ix));

hits[..] |= mask;          // 去重：同一个子采样点只算一次
coverage = popcount(mask) / 9.0f;
```

### 4.2 为什么它算的是面积

9 个点里命中 k 个，覆盖率就是 `k/9`——这正是**用有限样本估计面积比例**（蒙特卡洛积分的确定性版本）。它有两个结构性保证：

- `coverage` 只能取 `{0, 1/9, …, 1}`，**不存在超过 1 的情况**（位运算天然去重，每个子样本最多贡献 1/9）；
- 值只由**本像素自己**的覆盖情况决定，能量不跨像素转移。

这两点让它与 MSAA 的语义完全一致：MSAA 就是「每像素 N 个固定位置样本，覆盖率 = 命中数 / N」。

### 4.3 SSAA 与 MSAA 不是同一件事

两者都用 N 个样本点估计覆盖率，但**「着色算几次」**不同，由此决定了能抗哪类锯齿：

| | SSAA（超级采样） | MSAA（多重采样） |
|---|---|---|
| 光栅化覆盖测试 | N 次 | N 次 |
| **像素着色** | **每子样本 1 次（N 倍开销）** | **每像素 1 次** |
| 存储 | N 倍分辨率的完整颜色缓冲 | 每像素 N 个样本（可压缩） |
| 能抗的锯齿 | 几何边缘 + 着色/高光 + 纹理 | **仅几何边缘** |
| 硬件支持 | 无（引擎里用“渲染大图再缩小”模拟） | 有（GPU 原生样本位置） |

- **SSAA**：把整幅画面按 2×2 渲染，每个子像素完整走着色（贴图、光照都算一遍），最后 4 个平均。什么锯齿都能治，代价是着色成本 ×4。
- **MSAA**：只在光栅化阶段保留 4 个子样本位置，着色只做一次，再把这一次的颜色写进所有被覆盖的样本，resolve 时按覆盖率平均。便宜，但**三角形内部的着色突变（镜面高光、纹理摩尔纹）它治不了**——因为一个像素只着色一次。

用图表示：

```
MSAA:  ┌─┬─┐  4 个样本位置，● = 被覆盖
       │●│○│  着色 1 次 → 颜色按 3/4 混合
       ├─┼─┤
       │●│●│
       └─┴─┘

SSAA:  ┌───┬───┐  每个格子里都完整算一次颜色
       │亮 │亮 │  再平均
       ├───┼───┤
       │亮 │暗 │
       └───┴───┘
```

**我们的实现属于 MSAA 语义**：只算覆盖率，颜色恒为同一个纯色。曲线是纯色时，MSAA 与 SSAA 结果完全一致（每个子样本颜色相同，按覆盖率混合 = 按面积平均）；如果曲线带渐变或贴图，SSAA 更准、MSAA 更省。

> 想让 MSAA 也按样本着色，GPU 提供了 `glSampleShading` / `SV_SampleIndex`，一旦开启它就退化成 SSAA。

### 4.4 包围盒为什么是 `-1 / +1`

被判定为「覆盖」的点集是**胶囊形**（线段与半径 0.5 的圆盘做 Minkowski 和），它的 x 范围是 `[minx − 0.5, maxx + 0.5]`。而第 x 列像素的子采样点只在 `[x + 1/6, x + 5/6]` 之内，于是：

```
左边界：x + 5/6 ≥ minx − 0.5   →  x ≥ minx − 4/3
右边界：x + 1/6 ≤ maxx + 0.5   →  x ≤ maxx + 1/3
```

代码里写的 `floor(minx) − 1` 和 `ceil(maxx) + 1` 是这个精确边界的**保守上界**（最多多算 1~2 列）。

这里的原则值得单独记一笔：**包围盒只是粗筛，宁可偏大、绝不能偏小**。偏大多算几个像素，偏小会让曲线出现缺口——代价完全不对称。渲染器里的 BVH 遍历、阴影裁剪、视锥剔除，全是同一个思路。

### 4.5 优缺点

| 优点 | 缺点 |
|---|---|
| 覆盖率有明确物理含义（面积比例） | 每像素 9 次距离计算，比 Splat 贵约 6 倍 |
| 结果可解释、可验证（总量 ≈ 真实面积） | 只有 9 级灰度，宽软边会出现阶梯 |
| 与采样密度无关（只依赖几何） | 需要线段结构（先离散成折线） |
| 与硬件 MSAA 语义一致，便于讨论 | 线宽、半像素约定必须想清楚 |

## 5. 实测对比

同一组控制点、同一批 1001 个采样点、同一合成函数，只换覆盖率算法（表中「3×3 覆盖率采样」即方法 B，与 MSAA 同语义）：

| 指标 | 无 AA | Splat | 3×3 覆盖率采样 |
|---|---|---|---|
| 有效像素数 | 541 | 1172 | 931 |
| 满值像素（255） | 541 | 438 | 67 |
| 中间值像素 | 0 | 734 | 864 |
| 灰阶种类 | 1 | 231 | **9** |
| 覆盖率总和 | 541.0 | 707.2（截断后） | 493.3 |
| 净渲染耗时 | ≈2 ms | ≈4 ms | ≈15 ms |

（耗时用 5 次取最快，已扣掉约 26 ms 的进程启动 + 读写图固定开销。）

三个关键读数：

1. **面积一致性**：方法 B 的 493.3 是三者中唯一接近「真实面积」的估计；无 AA 的 541 因为阶梯多算了像素；Splat 的 707 是截断后的残余。
2. **灰阶分布**：Splat 231 级 → 视觉平滑；方法 B 只有 9 级（每级 11.1%）→ 放大后能看出等值线状的台阶。
3. **满值像素**：方法 B 只有 67 个满值，绝大多数像素是部分覆盖——这是「1 像素宽的斜线」应有的样子；无 AA 则 100% 满值。

## 6. 怎么选

| 场景 | 推荐 |
|---|---|
| 曲线/折线/描边，要求结果接近物理面积 | **方法 B（覆盖率采样）**，或直接解析距离场 `α = clamp(0.5 + 0.5 − d, 0, 1)` |
| 点云、粒子、散点、稀疏采样 | **Splat**（本来就是能量累加） |
| 实时性敏感、边缘质量要求一般 | **Splat**，注意按采样间距归一化 |
| 需要高质量宽软边（阴影、模糊） | 两者都不够：用可分离高斯 + 更多级灰度 |
| 单像素几何边缘（三角形） | MSAA（硬件）；后处理则 FXAA/TAA |

一个常被忽略的第三种写法：**解析覆盖率**。如果几何足够简单（直线、圆），可以直接算「像素方形与带子的交集面积」，得到**连续**的 α，既没有 1/9 量化台阶，也不像 Splat 那样饱和——代价是需要解析求交，CPU 上比 SSAA 还贵，但 GPU 上用 SDF + `smoothstep` 几乎是免费午餐。

## 7. 六个容易踩的坑

1. **`coverage` 的语义不同**：Splat 的是能量（可 > 1），方法 B 的是面积（≤ 1）。同名字段不代表可以互相比较。
2. **`min(1, ·)` 是截断，不是归一化**。Splat 被截掉 29% 的能量，想保能量守恒应该除以最大值或按 `1−(1−a)(1−b)` 做并集混合。
3. **`+0.5f` 是四舍五入**。`static_cast<uchar>` 是截断，不加 0.5 会让所有中间值系统性偏暗半个色阶。
4. **半像素约定**：本文代码里 `(x, y)` 是像素格子的**左上角**（像素覆盖 `[x, x+1]`），而 OpenCV 的 `cv::line`/`cv::circle` 用**像素中心**约定。两者差 0.5 像素，混用时会出现「曲线与标记整体错位半像素」。
5. **线宽的定义**：方法 B 里的 `half_width = 0.5` 是「1× 分辨率下的 1 像素」。如果把整图放大 3 倍再画，半宽也要跟着变成 1.5，否则线会变细。
6. **sRGB 混合**：`bg·(1−α) + c·α` 应该在线性光强空间做。当前代码直接在 sRGB 编码值上混合，半覆盖像素会偏暗（α=0.5 时 128 而非 187）。1px 细线上看不出来，但做大幅羽化/阴影时会非常明显。

## 8. 与工业界方法的关系

| 方法 | 覆盖率怎么来 | 我们的对应 |
|---|---|---|
| 覆盖率采样（coverage AA / MSAA 语义） | 每像素 N 个位置做覆盖测试，颜色只算一次 | **就是本文方法 B**（9 样本版） |
| SSAA（超级采样） | 高分辨率渲染，每个子像素完整着色后降采样 | 不是方法 B；曲线为纯色时两者结果重合 |
| MSAA（硬件多重采样） | 几何阶段在子样本位置做覆盖测试，resolve 时按覆盖率混色 | 语义相同；B 没有几何光栅化阶段，直接对距离场测试 |
| 解析 AA / SDF | 距离场 + `smoothstep`，α 连续 | B 的连续版本，GPU 上最常见 |
| FXAA | 后处理：检测边缘 → 沿边缘方向模糊 | 与几何无关，不适用于 1px 线（会把线抹糊） |
| TAA | 多帧抖动 + 时域累积 | 依赖运动矢量，静态图无收益 |
| 后滤波（Splat） | 用重建核对样本做卷积 | **就是本文方法 A** |

**Unity 对照**：

- `Quality Settings → Anti Aliasing`：硬件 MSAA（前向渲染下生效）；
- URP 的 MSAA 在 Renderer Data 里配置，走的是 `RenderTexture` 的 samples 参数；
- Post Processing 里的 FXAA/SMAA/TAA 是后处理链路；
- Shader 里手写的抗锯齿（描边、圆形进度条、UI 圆角）通常是 SDF + `fwidth`/`smoothstep`——正是「解析 AA」；
- 粒子/拖尾在 CPU 端按覆盖率混合时，本质就是 Splat 那套能量累加。

## 9. 可以继续做的实验

1. 把 `n` 改成 4（16 样本）：灰阶从 9 级升到 17 级，看台阶是否消失，耗时增加多少。
2. 给 Splat 乘上 `Δs` 归一化，验证「总能量 ≈ 真实面积」。
3. 把合成改成线性空间混合，量化 1px 线在两种空间下的亮度差。
4. 用解析求交算真正的面积覆盖率，和方法 B 的误差做对比（预期误差在 1/(2n) 量级）。
5. 交互模式（`1/2/3` 键）下观察三条画法对**曲线交叉点**的处理差异——Splat 会在交叉处过亮，方法 B 不会。
